# Standing Rules

> Rules that hold across every project unless a project says otherwise.
> Keep this short. A rule nobody reads is not a rule.

## Where things go

- Raw material I've just dropped in and haven't sorted → `_inbox\`
- Anything belonging to one project → `projects\<project>\`
  - `inputs\` — source material, unmodified. Never edit a file here.
  - `working\` — drafts, scratch, analysis in progress. Assume it's messy.
  - `outputs\` — the finished thing for that project.
- Finished work spanning several projects → `outputs\`
- Templates, style guides, boilerplate, past work worth imitating → `_reference\`
- Done and cold → `_archive\`. Move, don't delete.

## Rules for Claude

1. **Never edit anything in an `inputs\` folder.** Read from it, write derivatives elsewhere.
2. **Don't overwrite my drafts.** New version, new filename. I'll do the deleting.
3. **Ask before restructuring folders.** Creating files inside the structure is fine.
4. **Cite sources for factual claims** in anything headed outward. A link or a page number.
5. **Flag uncertainty explicitly.** Mark guesses as guesses. I would rather see a gap than a confident invention.
6. **Read `_admin\about-me.md` and `_admin\voice.md`** before drafting anything I'll put my name on.
7. **Check `_reference\` for a template** before inventing a format from scratch.

## File naming

`YYYY-MM-DD-short-description.ext` for anything dated.

Nothing goes to a colleague, a client, or a government counterpart without me
reading it end to end first. Claude drafts; I sign.
